## 跨报告同根因归并

9 个代理彼此不可见，因此同一个根因会在多份报告中以不同视角出现。修复时应按**簇**推进，而不是按报告逐条推进。

### 簇 A — "静默漏票"（最高业务风险）
发票被发现却在没有任何用户可见提示的情况下丢弃。
`EXT-01`（通用文件名导致 PDF 删掉另一张发票的 OFD）、`EXT-02`（直链只探测前 8 个且只信 HEAD）、`EXT-03`（SiteHandler 无法表达部分失败）、`EXT-04`（所有 inline 图片被当签名图丢弃）、`EXT-05`（32 MiB 上限）、`EXT-07`（跨来源重复件双重归档）、`EXT-11`（缺 `source` 静默跳过）、`CORE-03`（重复/缺失 `Message-Id` 折叠不同邮件）。

### 簇 B — 事务与并发完整性（数据可能不一致）
`CORE-01`（`--state` 改锁目录不改归档目标，两进程同写台账）、`CORE-02`（fatal 后其他 worker 继续归档）、`CORE-06`（`--dry-run` 仍改写 state 且不持锁）、`OCR-02`（父进程崩溃致租约双持有）、`OCR-03`（CSV 未 fsync 就提交 journal）、`OCR-04`（stale-lock CAS 剥掉新锁）、`OCR-05`（不可恢复的 `prepared` 事务）、`OCR-06`/`OCR-07`（PID 复用、`.staging` 无恢复）、`ELEC-02`（协调器未覆盖 reset / pending 重写 / 锁前配置写入）。
门禁缺口：`TEST-08`、`TEST-10` —— 这两条正是本簇缺少回归测试的证据。

### 簇 C — "失败被报成成功"（贯穿后端→IPC→UI→文案的同一条链）
这是本轮跨层重复度最高的问题，四份报告各自独立命中：
后端 `CORE-04`、`CORE-09` → 主进程 `ELEC-08`、`ELEC-12` → 渲染层 `FE-01`、`FE-04` → 文案 `COPY-01`、`COPY-02`、`COPY-04`、`COPY-05`。
应作为**一条纵向修复**处理：确立"部分成功"这一一等状态，让它从 CLI 退出码一路贯通到 toast 文案，而不是在四层各打一个补丁。

### 簇 D — 敏感信息泄漏
`CORE-08`（签名 URL 进日志与 pending reason）、`CORE-13`（logger 不转义换行可破坏进度协议）、`ELEC-07`（邮箱/主题/原始错误/绝对路径绕过脱敏进 renderer）、`COPY-06`、`COPY-11`、`COPY-15`、`HYG-01`（**真实发票与邮件元数据已进公开 Git 历史**）、`HYG-02`（`.gitignore` 漏掉含凭据的临时文件）。
`HYG-01` 需要人工决策是否重写历史，不能由自动化处理。

### 簇 E — 安全边界
`ELEC-01`（破坏性 reset 的授权只在 renderer，主进程可直接调用删除财务原件）、`ELEC-05`（`MFH_DATA_DIR` 跳过单实例锁）、`ELEC-06`（`open-path` 允许根可被 renderer 改写 + pending hash 路径穿越）、`OCR-01`（重定向 SSRF 校验发生在内网请求之后）、`EXT-06`（旧百望接口明文 HTTP 取下载地址）、`OCR-11`（固定假数据的 mock OCR provider 可由生产配置启用）、`FE-05`（CSV/Excel 公式注入）。

### 簇 F — 结构性巨石
`ELEC-13`（`main.ts` 2466 行 / 13 类职责）、`CORE-12`（`cmdRun`、`processMail` 200 行级编排）、`OCR-15`（`efapiao.ts` 682 行 god-module）、以及 `gui-design/scripts/shell.js` 3031 行单文件渲染层（05 报告给出了拆分方案）。
这一簇不修复不会立刻出故障，但簇 B 和簇 E 的边界之所以难以集中审查，根因就在这里。建议在修完 P0 后、动结构之前先补齐簇 B 的回归测试。

### 簇 G — UI 可用性
按钮/布局：`UI-02`（默认窗口宽度裁切首屏长按钮）、`UI-03`（侧栏完整邮箱挤压时钟与主题按钮）、`UI-04`（"关于"页完整路径撑破卡片）——07 报告对每一处都给出了具体的缩短中文措辞或放宽容器的方案。
动画缺失：`UI-05`（无真实路由过渡）、`UI-06`（accordion `0`→`none` 无法动画）、`UI-07`（toast 只有进入动画，退出瞬间删除）。
Toast 机制本身：`FE-09`（toast 拦截点击，旧问题仍在）、`FE-10`（toast 生命周期删除尚未确认的错误）、`FE-07`（IPC 拒绝永久卡住停止按钮）。
状态误导：`UI-01`（未配置/未验证邮箱仍显示绿色脉冲"在线"）。
